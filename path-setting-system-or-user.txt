# PHP にパスを通すには、システム環境変数かユーザー環境変数か？

結論からもうしあげますと、
最初はユーザー環境変数に設定して、
必要に応じてシステム環境変数に変更します。

PHP の実行ファイルがあるディレクトリを 環境変数の Path に設定します
そうすると、コマンドプロンプトなどのターミナルで
PHP が実行できるようになります。

環境変数の Path を設定することを、
PHP に Path を通すと表現します。

たとえば、MAMP を使用していて、php のバージョンが
php8.3.1なら
```
C:\Mamp\bin\php\php8.3.1
```
を Path として環境変数に設定します。

Path の設定のときに、システム環境変数とユーザー環境変数の
どちらに設定するか？

と疑問に思うかもしれません。

## ざっくりとした説明
- 最初はユーザー環境変数に設定して、
　必要に応じてシステム環境変数に変更します

 個人の学習においては、ユーザー環境変数で十分だからです

 
>注意事項として、
Path を変更した後は、ターミナルや VS Code が
すでに起動している場合は再起動します、
ターミナルや VS Code など、
起動済みのプロセスは変更前の環境変数を持っているからです
php -v で Path が設定されたかを確認する際は気を付けるところです

>なお、
 > ```
  >where php
  >```
  >としてどこの php が選ばれたか確認してから、
  >```
  >php -V
  >```
  >で php が実行できるかを確認すると確実です。

 

## さらに説明しますと
- ユーザー環境変数に PHP の Path を設定する場合は、
PHP を使用するユーザーごとに
設定をする必要があります

- SYSTEM アカウントなど、ユーザー環境変数を持たないアカウントで
PHP を使用するときは、
システム環境変数に Path を設定

- システム環境変数に設定すれば、
すべてのユーザー、管理者権限、SYSTEM アカウントで
原則は使用可能です、
ただし、個別ユーザーの Path 設定、
実行環境の環境変数上書き、
再起動していないターミナルなどで期待どおりにならないケースはあります

- 管理者として Composer を起動する場合は
同じユーザーの環境変数が設定されていれば、
一般的に引き継がれます

- PHP の実行ファイルが複数存在する場合は、
where php で優先される PHP を確認します
 ```cmd
 where php
 ```

- ユーザー環境変数と
システム環境変数の設定が重複した場合は
ユーザー環境変数が優先されます

- 環境変数の設定が PC 全体に影響することを避けたい場合は、
ユーザー環境変数に設定
