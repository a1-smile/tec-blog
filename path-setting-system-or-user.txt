# PHP にパスを通すには、システム環境変数かユーザー環境変数か？

php や composer を任意のディレクトリから実行するために
PHP の実行ファイルがあるディレクトリを Path に追加します。
このことを
PHP にパスを通すと表現します。

たとえば、MAMP を使用していて、php のバージョンが
php8.3.1なら
```
C:\Mamp\bin\php\php8.3.1
```
を Path として環境変数に設定します。

Path の設定のときに、システム環境変数かユーザー環境変数か、
どちらに設定するか？

と疑問に思うかもしれません。

## ざっくりとした説明

- 個人の開発 PC ならユーザー環境変数

- 複数ユーザーで使うならシステム環境変数

- ユーザーがログインしていない状態でも PHP を実行する仕組みでは、システム環境変数に設定します

- Path を変更した後は、すでに起動しているターミナルや VS Code を
  再起動します、
  ターミナルや VS Code など、
  起動済みのプロセスは変更前の環境変数を持っているからです
  php -v で Path が設定されたかを確認する際は気を付けるところです

なお、
  ```
  where php
  ```
  としてどこの php が選ばれたか確認してから、
  ```
  php -V
  ```
  で php が実行できるかを確認します。

 

## さらに説明しますと
- ユーザー環境変数に Path を設定する場合は、
Composer を使用するユーザーごとに
 Path 設定をする必要があります

- SYSTEM アカウントなど、ユーザー環境変数を持たないアカウントで
 composer を使用するときは、
システム環境変数に Path を設定

- 管理者として Composer を起動した場合は
同じユーザーの環境変数が設定されていれば、
一般的に引き継がれます

- システム環境変数に設定すれば、
すべてのユーザー、管理者権限、SYSTEM アカウントで
原則は使用可能です、
ただし、個別ユーザーの Path 設定、
実行環境の環境変数上書き、
再起動していないターミナルなどで期待どおりにならないケースはあります

同じコマンド名の PHP が複数存在する場合は、
where php で優先される PHP を確認します


- Composer のセットアップ時にすべてのユーザーで使用するという
設定にした場合でも、
 Path をユーザー環境変数に設定して
ユーザーとして使用する場合は、整合性に通常は問題ありません。
コマンドプロンプト、PowerShell、VS Codeは、有効な Path として
ユーザー環境変数とシステム環境変数の両方を持ちます

- Windows サービス、タスク スケジューラ、CI、別ユーザーでの実行では
ユーザー環境変数の Path が有効にならない場合があります
これを回避するためには、システム環境変数に Path を設定します

- 環境変数の設定が PC 全体に影響することを避けたい場合は、
ユーザー環境変数に設定
